# MYSQL
## 索引
### 覆盖索引
回表：依据索引查不需要的数据，需要（回到主键索引树重新搜索）查询拿到数据，称为回表
覆盖索引：避免回表，通过在索引中添加需要的字段达到不需要回表，从而提高查询性能（是否一定需要覆盖索引需要视情况而定）
### 联合索引
最左前缀原则：因为innodb使用的是b+树，索引项是按照索引定义里面出现的字段顺序排序的，一旦最左匹配，则顺序遍历拿到需要的结果。
- 问：如果有一个联合索引index（a,b,c）使用查询条件where b = yyy and a = xxx,是否可以利用到这个索引？
  - 可以。联合索引只要存在最左前缀匹配即可，不需要在语法上要求保证顺序，mysql优化器会进行优化处理
- 问：如果有一个联合索引index（a,b,c）使用查询条件where c = xxx and b = yyy,查询条件是右边开始匹配的，可以利用到这个联合索引吗
  - 不可以，最左前缀原则
### 索引下推（作为了解）
在使用联合索引基础上的，mysql引擎的优化，最左前缀已经匹配，那第2个索引是如何过滤的呢。
- 在MySQL 5.6之前，只能从ID3开始一个个回表。到主键索引上找出数据行，再对比字段值。

- 而MySQL 5.6 引入的索引下推优化（index condition pushdown)， 可以在索引遍历过程中，对索引中包含的字段先做判断，直接过滤掉不满足条件的记录，减少回表次数。

## 问题汇总
### 列属性not null default 'xxx'，实际插入列为空的报错："Column 'xxx' cannot be null"
使用一些orm框架时，有一些方法形如insertSelective，对为null的字段（列）实际上并不会插入或更新，即不会操作，不会触发数据库 not null default 'xxx'的处理。因而出现这种报错。
